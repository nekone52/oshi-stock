# 設計メモ(推しストック)

このメモは、ER図・画面遷移図・Issue の変更点と、その理由をまとめたものです。

## 画面
- 画面遷移図(Figma): ワイヤーフレームで、ホーム・ログイン・予約・グッズ・ほしい物・設定などを描いている。
- 下のメニュー(ホーム / グッズ / 推し / 予約 / 設定)は、全画面共通。
- ログイン(認証)は未実装。ログイン後にホームへ進む流れは、Issue #34 で作る。

## データベース(ER図)
- **users / sessions**: Rails 8 の標準認証で自動生成。
- **characters(推しキャラクター)**: user_id で、ユーザーに紐づく。
- **items(グッズ)**: 今の状態だけを持つ。
  - `name` / `url`(参考URL)
  - `shipping_date`(文字列): 発送時期の表示用。「10月上旬」などを書く。
  - `release_month`(date): 発売月。並べ替えと、月ごとのまとめに使う。入力は月だけでよい。
  - `status`(integer): wanted / reserved / owned の3つだけ。
  - `paid`(boolean): 支払い済みかどうか。所持後も確認できるよう、status から分けている。
  - `payment_deadline`(date): 支払い期限。残り日数の表示や警告に使う。日まで必要なため date。
  - `character_id`(FK): どのキャラのグッズか。
- **purchase_logs(購入履歴)**: 購入1回につき1行。items と1対多。
  - `item_id`(FK)
  - `purchased_month`(date): 購入した年月。日は1日で保存。
  - `purchased_period`(文字列): 上旬・中旬・下旬など。
  - `price`(integer): 税込の円。
  - `shop_name`(文字列): 購入店舗。

## 決めたこと
- 購入の情報(日・金額・店)は、items ではなく purchase_logs に持つ。同じグッズを2回買う場合や、後から振り返る場合に対応するため。
- 発送時期(表示)と、発売月(並べ替え)は、役割を分けて2つの列にする。
- MVP では、発売順の並べ替えは入れない。本リリースで対応する。README の説明も、その前提に合わせている。
- キャラを削除すると、紐づくグッズも一緒に削除する(`dependent: :destroy`)。削除確認ダイアログに、その旨を表示する(Issue #22)。
- グッズの登録・編集では、character_id がログイン中のユーザーのキャラか、コントローラ側で必ず確認する。
